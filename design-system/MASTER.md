## 1. 五条设计原则

1. **一致性优先于风格新鲜度。** 已交付的 `prototype-x-style.html` 与 `prototype-collection-room.html` 是同一个产品的两个视图。设计工具曾推荐紫色 Vibrant & Block 风格，**明确不采纳**——换主色会把一个产品拆成两个 App。品牌蓝 `#1d9bf0` 冻结。
2. **订阅语义必须可见。** 用户看到什么，由订阅关系决定。任何排序、置顶、推荐都必须显示理由（「为什么推荐」「已订阅」「本房间新增 N 集」），禁止不可解释的重排。
3. **合规即界面，不是脚注。** 来源署名、许可徽章、AI 摘要标记、举报入口、外链同意、审核中状态，**都是必显的一等组件**，不是可折叠的次要信息。NLA 与 OSA 的合规在界面上要看得见。
4. **简繁中文是一等公民。** `zh-Hans` / `zh-Hant` 双文案；繁体用 Noto 字体栈；不加载任何外部字体资源（UK GDPR + 离线可用 + 单文件零依赖）。英文地名、金额、日期按英国本地习惯。
5. **无障碍是地基，不是补丁。** WCAG 2.2 AA 起步：4.5:1 正文对比、3:1 控件边界、44px 触控目标、可见焦点环、`prefers-reduced-motion`、200% 缩放不破版、颜色绝不作为唯一状态指示。

### 2.3 对比度审计（实测，非估算）

| 组合 | 实测 | 结论 |
|---|---|---|
| `#1d9bf0` 文字 / 白底 | **3.00:1** | ❌ 小字链接不达 AA |
| 白字 / `#1d9bf0` 按钮 | **3.00:1** | ❌ 主按钮文字不达 AA |
| `#00ba7c` / 白底 | **2.53:1** | ❌ 旧 `--good` 不可读 |
| `#ffad1f` / 白底 | **1.87:1** | ❌ 旧 `--warn` 不可读 |
| `#71767b` / `#16181c` | **3.88:1** | ❌ 旧深色次要文字在卡片上不达 AA |
| `#d02b32` / 黑底 | **4.07:1** | ❌ 旧深色 danger 不达 AA |

**根因**：把「品牌装饰色」和「可读文字色」当成一个变量用。**解法是分离，不是改品牌色**：

| Token | Light | Dark | 用途 | 对比度 |
|---|---|---|---|---|
| `--accent` | `#1d9bf0` | `#1d9bf0` | **仅装饰**：Tab 下划线、焦点环、脉冲点、进度条、soft 背景 | 焦点环 3.00 / 7.00（≥3:1 达标） |
| `--accent-ink` | `#0a6ba8` | `#1d9bf0` | **链接、强调文字、链接型徽章** | 5.70 / 7.00 |
| `--accent-strong` | `#0a72b4` | `#1d9bf0` | **按钮实底** | — |
| `--on-accent` | `#ffffff` | `#0f1419` | **按钮文字**（与 strong 成对使用） | 5.15 / 6.17 |
| `--focus` | `#0a6ba8` | `#1d9bf0` | **仅焦点环**（品牌蓝在浅色卡片上 2.84:1 不达标） | 5.40 / 5.92 |

> 深色主题按钮是「亮蓝底 + 近黑字」，浅色是「深蓝底 + 白字」。这不是配色不一致，而是**为保持同一品牌蓝而做的可读性配对**，属于设计系统的标准做法。

**第五个 token：`--focus`。** 对比度门禁第一次运行时抓到一个此前未算到的缺陷：`#1d9bf0` 在浅色 `--surface`（`#f7f9f9`）上只有 **2.84:1**，低于 WCAG 1.4.11 对焦点指示的 3:1 要求——即「页面底的焦点环合格、卡片内的焦点环不合格」。因此独立定义 `--focus`（浅 `#0a6ba8` 5.40:1 / 深 `#1d9bf0` 5.92:1），`:focus-visible` 一律用它，**不再用品牌色**。这五列 token 的每一对都由 `check-contrast.py` 断言，改值必须重跑。

## 3. 设计基础（Design Foundations）

### 3.1 颜色系统

**中性表面（三层递进）**：`--bg` 页面 → `--surface` 卡片 → `--surface2` 输入/chip/进度槽。分隔线 `--border`，控件边界 `--line`（两者职责不同，禁止混用）。

| 角色 | Light | Dark | 用途 |
|---|---|---|---|
| `--bg` | `#ffffff` | `#000000` | 页面底 |
| `--surface` | `#f7f9f9` | `#16181c` | 卡片、侧栏盒 |
| `--surface2` | `#eff3f4` | `#202327` | 输入框底、chip、进度槽 |
| `--text` | `#0f1419` | `#e7e9ea` | 正文、标题 |
| `--muted` | `#536471` | `#9aa6b1` | 时间、说明、次要信息 |
| `--border` | `#e6ecf0` | `#2f3336` | 列表/卡片分隔线 |
| `--line` | `#707c87` | `#6d7781` | 输入框、描边按钮、徽章边框 |
| `--chip` | `#eff3f4` | `#202327` | 标签底、房间类型 chip |

**语义色**（文字态 / 实底态分离）：

| 语义 | Light 文字 | Dark 文字 | 实底 `--good-solid` | 实底文字 `--on-good` | 软底 |
|---|---|---|---|---|---|
| 成功 / 已通过 | `#00875a` (4.55) | `#3ccf91` (10.53) | 浅 `#00875a` / 深 `#3ccf91` | 浅白 / 深 `#0f1419` | `--good-soft` |
| 警告 / 待审核 | `#a86800` (4.52) | `#e0a838` (9.83) | 不做实底按钮 | — | `--warn-soft` |
| 危险 / 举报 / 错误 | `#d02b32` (5.16) | `#f07579` (7.53) | 不做实底按钮 | — | `--danger-soft` |

> **禁止**：用 `--good` 作深底 + 白字（深色主题下亮绿配白字严重不足）；用 `--accent` 作浅色正文链接；用 `--border` 作输入框边框；用颜色单独表达状态。

### 3.2 字体系统

```
--font-sans:  -apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans TC",
              "Noto Sans SC", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif
--font-serif: "Noto Serif TC", "Songti SC", "SimSun", serif   /* 仅房间封面 / 影视标题 */
```

- **不加载外部字体**（无 Google Fonts / CDN 字体）：UK GDPR 下第三方字体请求会传 IP；同时保证原型单文件离线可跑。
- 简繁共存：`Noto Sans TC` 在前可让繁体字形优先，简体由 `Noto Sans SC` / `PingFang SC` 兜底。
- **字阶**：11 / 12 / 13 / 14 / 15 / 16 / 17 / 19 / 21 / 30 px。**移动端帖子正文 15px、行高 1.5**（v2.3，`--fs-body-mobile` / `--lh-body-mobile`，作用于卡片正文、频道与房间帖子正文、留言、发布页信息流）；输入框与 textarea 仍 ≥16px（防 iOS 聚焦放大）；标题、按钮、触控目标规则不变；桌面默认 15px，卡片正文 14px。
- **字重**：400 正文 / 500 Tab 未选中 / 600 徽章与按钮 / 700 标题与强调 / 800 页面标题与卡片主标题。
- **行高**：标题 1.35–1.4，正文 **1.6**，说明文字 1.75。正文行长上限 `68ch`。
- **数字与金额**：英国本地格式 `£1,250`、`07:00`、`09/11/2026`，使用等宽数字 `font-variant-numeric: tabular-nums`。

### 3.3 间距系统

基准 **4px**，节奏 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / **44（触控）** / 48 / 64。
- 卡片内边距 14–16px；列表行 12–16px；区块间距 16px；侧栏盒间距 14–16px。
- 任何可点击元素的最小高度 = `--tap: 44px`；相邻触控目标间距 ≥8px。

### 3.4 圆角 / 阴影 / 层级

| Token | 值 | 用于 |
|---|---|---|
| `--r-sm` | 6px | 徽章、许可角标、焦点环圆角 |
| `--r-md` | 10px | 输入框、集号方块、头像方块、嵌入槽 |
| `--r-lg` | 14px | 卡片、bundle、来源块、片单卡 |
| `--r-xl` | 16px | 侧栏盒 |
| `--r-pill` | 999px | 按钮、Tab chip、搜索框、Toast |

阴影只有一级 `--shadow`（浅 `rgba(0,0,0,.08)` / 深 `.5`），用于浮层与移动预览外框；**卡片不靠阴影分层，靠边框与表面色**。

`z-index` 固定阶梯：`20` 吸顶栏 → `30` 底部 Tab → `50` Toast → `60` Modal。禁止出现其他数值。

### 3.5 动效

| Token | 值 | 用途 |
|---|---|---|
| `--dur-fast` | 150ms | hover / 颜色变化 |
| `--dur-base` | 220ms | 展开、进度、Toast、卡片切换 |
| `--dur-slow` | 300ms | 页面级过渡（上限，不超过 300ms） |
| `--ease-out` | cubic-bezier(.2,.8,.2,1) | 进入 |
| `--ease-in` | cubic-bezier(.4,0,1,1) | 退出 |

**硬规则**：只动画 `transform` / `opacity` / `color` / `background-color`；禁止动画 `width` / `height` / `top` / `left`（会造成重排与布局跳动）。hover 用颜色/透明度，**禁止 `transform: scale()` 造成布局位移**。每个视图同时运动的 elements ≤2。`prefers-reduced-motion: reduce` 下全部关闭。

### 3.6 图标

- 统一 **24×24 viewBox 的 SVG `<symbol>` sprite**，`.ico` = 20×20、`.ico.sm` = 16×16，线宽 1.8，`stroke: currentColor`。
- **禁止 emoji 与 Unicode 字符当图标**（`⌂ ＋ ⌕ ♡ ▤ ◉ ✓ ↗` 一律替换）。
- 纯图标按钮必须带 `aria-label`；装饰性图标 `aria-hidden="true"`。
- 房间原型已有 23 个 symbol，作为全站图标集基线；新增图标必须先用同一线宽与圆角风格绘制。

## 4. 唯一 Token 清单与禁令

完整值见 `tokens.css`。**组件代码中出现以下写法即为 QA 不通过**：

```css
/* ❌ 禁止 */
color: #1d9bf0;              /* 硬编码品牌色，且浅色下不达 AA */
border: 1px solid #ccc;      /* 硬编码控件边框 */
min-height: 40px;            /* 低于 44px 触控目标 */
z-index: 999;                /* 越出层级阶梯 */
transition: all .5s;         /* 超长 + 动画布局属性 */

/* ✅ 正确 */
color: var(--accent-ink);
border: 1px solid var(--line);
min-height: var(--tap);
z-index: var(--z-toast);
transition: opacity var(--dur-fast) var(--ease-out);
```

允许的例外：半透明叠加（`rgba()`）用于 soft 背景、播放器渐变遮罩；示例数据里的纯色占位封面（不承载信息）。

## 5. 组件库

命名采用 **PascalCase**（Vue SFC 文件名与 `<script setup>` 导入名一致，如 `EmbedPlayerCard.vue`）。每个组件必须定义 TS `defineProps`、用 `emit` 回传状态、不直接修改 props；可选项用 `withDefaults`。

### 5.1 基础组件

| 组件 | 结构 / 尺寸 | 变体 | 状态 | 无障碍 |
|---|---|---|---|---|
| `BaseButton` | 高 44px，圆角 pill，横向 padding 16px，gap 8px | `primary` / `outline` / `solid-dark` / `ghost` / `danger` / `sm` | default / hover / active(opacity .82) / focus-visible / disabled(opacity .5, not-allowed) / loading（禁用 + skeleton 文案） | 原生 `<button>`；`aria-busy` 于 loading；纯图标需 `aria-label` |
| `IconButton` | **44×44** 圆形 | default / hover(soft 底) | 同上 | 必须 `aria-label` + `aria-pressed`（可切换时） |
| `TextField` / `SelectField` / `TextArea` | 高 44px，圆角 10px，边框 `--line` | 默认 / 错误 / 禁用 | `:focus-visible` 边框改 `--accent`；`aria-invalid="true"` 边框改 `--danger` | `<label for>` 与 `id` 一一对应；错误文字 `role="alert"` + `aria-live="polite"`；`aria-describedby` 指向帮助文字 |
| `Checkbox` | 20×20，`accent-color: var(--accent-strong)` | 默认 / 选中 | 键盘 Space 可切 | label 可点击（`for`/`id`）；版权确认项必须含完整说明文字 |

| `Avatar` | 38 / 42 / 44px，色块 + 首字 | 圆形（人）/ 12px 圆角（频道） | 静态 | `aria-hidden`，相邻文字已含名称 |
| `BaseCard` | 圆角 14px，边框 `--border`，表面 `--surface` | 可点击 / 静态 | hover 背景 `--hover`（不改尺寸） | 可点击卡用 `role="button"` + `tabindex="0"` + 键盘 Enter/Space |

## 6. 响应式框架

| 断点 | 布局 | 关键变化 |
|---|---|---|
| ≥1100px | 三栏 `240px / minmax(0,1fr) / 320px`，max-width 1280px | 左导航 sticky 100vh，右栏 sticky + 独立滚动 |
| 760–1099px | 两栏 `240px / 1fr` | **隐藏右栏**；主栏去掉右边框 |

**硬规则**：
- `<meta name="viewport" content="width=device-width, initial-scale=1">` 必须存在。
- `overflow-x: hidden` + 所有长文本 `min-width:0` / `text-overflow: ellipsis`，375px 下不得横向滚动。
- 吸顶栏内容需预留高度，不得遮挡正文；固定底栏必须有等量 `padding-bottom`。
- 200% 浏览器文字缩放时布局不破（用相对单位与 flex-wrap，不固定高度）。
- 验收宽度：**375 / 420 / 768 / 1024 / 1440 px** 逐个走查。

## 7. 合规 UI 规范（海外圈不可协商项）

> 这一章是产品独有的。开发最容易漏的恰恰是这些「看起来像装饰」的元素——它们是 NLA 核查、Ofcom 检查和 OSA 审计时界面侧的证据。

### 7.1 来源与许可（必显）

每张资讯卡必须同时具备：① 来源名称；② 许可徽章（`OGL v3.0` / `NLA 授权` / `UGC` / `原创`）；③ 原文回链（新窗口 `target="_blank" rel="noopener"`）；④ 多源事件可展开的来源列表。
**禁止**：把来源块做成默认折叠、把许可角标做成 hover 才出现的 tooltip、用「来源见原文」代替署名。

### 7.2 内容状态徽章（四态文案冻结）

| 状态 | 徽章色 | 文案（简体 / 繁体） | 交互 |
|---|---|---|---|
| 待审核 | `--warn` | 審核中 / 审核中，仅自己可见 | 不可分享、不可进推荐 |
| 英区无授权 | `--warn` | 僅登記 · 暫無合法入口 | 不给播放按钮，不进白名单 |
| 源站禁止嵌入 | `--warn` | 去原站看 | 自动降级为跳转卡，**禁止破解** |
| 原创已确认 | `--good` | 原創 · 版權已確認 | 显示 sha256 登记与审核时间 |
| 官方外链 | `--accent-ink` | 官方外鏈卡片 | 显示平台徽章 |

所有状态必须 **文字 + SVG + 颜色** 三重编码，且文字在简繁两套文案表里成对维护。

### 7.3 外链内联播放（见 PRD §24）

`EmbedPlayerCard` 状态机：`placeholder → consent → player → (收起，销毁 iframe DOM)`。
- 占位卡必须写明「将加载第三方播放器并传输你的 IP / 设备信息」；
- 三选项：`仅本次加载` / `总是允许此平台` / `去原站看`；持久偏好必须可撤回并写入 `user_consent_log`；
- 收起必须**销毁** iframe，不能 `display:none`；
- CSP `frame-src` 只列白名单；iframe 地址只能服务端下发；
- embed 卡**不进「为你推荐」、不置顶、不推送、不进每日精选**，界面上以「仅在已订阅频道出现」说明。

### 7.4 媒体与版权

- 剧集房间、电影房间**没有上传控件**（表单层就堵死）；上传入口只存在于原创视频房间，且必须勾选版权确认（人物同意 / 无未授权音乐或影视片段）。
- 视频卡片区分「原创」（可托管）与「官方外链」（不落文件）；不显示盗版站链接、不显示官方海报。
- 每条内容常驻举报入口；举报后 UI 显示受理状态与 24h SLA 说明。

### 7.5 推荐可解释性

「为你推荐」每张卡显示 `WhyChip` 与「减少此类内容」；「正在关注」显示「严格按时间排序 · 仅显示已加入的 N 个频道」。两句话不是修饰文案，是 UK GDPR 下对用户说明数据使用的界面证据。

### 7.6 简繁与主题

- `data-theme="light|dark"` 与 `lang="zh-Hans|zh-Hant"` 是两个独立维度，互不耦合；切换后用户偏好需持久化并可撤回。
- 所有合规文案、状态文案、按钮文案必须有简繁两份；**不得在繁体界面里混入简体状态词**（示例房间用繁体，即为此做的示范）。

`check-discover.js` 守卫「发现 = 看内容，分类 = 作用域」这条信息架构：真实执行 `renderDiscover()` 的 10 个分支（全部 / 国际地区、分类筛选与回落、搜索命中与无结果、未开法域、频道详情、访客模式），断言主体是 `cardHTML` 内容卡而非频道目录网格、房间投稿与 `norec` 分类信息不进顶层流、置顶优先 + 时间新鲜度、每张卡带「进频道」来源入口与右上角关注按钮、相关频道推荐位 ≤3、分类按钮只列有内容类目、空态有可执行下一步、动态 HTML 标签平衡。断言按**数据自洽**计算期望值而非硬编码条数，内容增减不会误报。

`check-flow.js` 守卫三个页面共用的演示数据层（§21）：内联副本与 `shared/ukcn-shared.js` 一致、登录 → 建房 → 发帖 → 审核中 → 模拟通过 → 加入 → 通知 → 重置全链路、「正在关注」置顶在前 + 严格时间倒序。`check-h5.js` 覆盖 v2.1 – v2.6 的 H5 流程（分类信息、AI 关键词、简繁、发现页头部、v2.5 交互细节、v2.6 站内信）。

v1.4 起，三道业务门禁同时断言 §17 的精简层：区域徽章只出现在顶部、卡片内无区域徽章、每卡右上角有 `CardJoinButton`（现文案为「关注」）、媒体块下方无 `data-media` 播放 / 静音按钮、播放与推荐参数收在顶部 `SettingsPanel` 且一次点击可达、设置面板内容始终被渲染（仅 `hidden` 控制可见性）。

**当前发布门槛（v2.6 起统一按「8 道 JS 门禁」计数，不再混用含 py 的序号）**：`check-ui` / `check-global` / `check-media` / `check-location` / `check-rooms` / `check-discover` / `check-flow` / `check-h5` 八道 JS 门禁 + `check-contrast.py` 全绿；另需 `sync-shared.js --check` 与 `gen-hant.py --check` 通过。历史演进：v1.5 六道 → v1.8 增 `check-flow` → v2.1 增 `check-h5`。

## 13. 待裴总确认（影响视觉，不阻塞开发）

1. **`--line` 已按合规值落到两份原型**：浅色 `#707c87`、深色 `#6d7781`，控件描边会比之前明显变重。这是为了满足 WCAG 1.4.11 的 3:1；若您更偏好轻盈观感，可回滚为「仅 `:focus-visible` 与错误态强制 3:1、常态描边用 `--border`」，但必须在无障碍评估里书面记录为已知偏差。请打开两份原型直接对比后拍板。
2. 深色主题主按钮采用「亮蓝底 + 近黑字」，是否接受与浅色「深蓝底 + 白字」的视觉反转？替代方案是两主题统一深蓝底 + 白字，代价是深色下品牌蓝不再作为按钮主色。
3. 是否把简繁切换做成首屏可见控件（当前设计放在设置里）？这会影响顶部工具栏图标数量与 44px 触控区排布。
4. ~~定位确认条用「常驻细条」还是「首次横幅、确认后收进设置」~~ **已由裴总第十轮反馈拍板（v1.4 / §17）**：选「首次横幅、确认后收成顶部一行细条，详情与开关收进右上角设置浮层」。来源与精度说明在首次条 + 设置面板两处都可见，§16.6 不丢失。
5. **未启用法域是否允许「申请开通」入口**（当前设计允许，作为下一法域排序依据）？若担心需求噪音或误以为承诺上线，可改为只展示人数、不放按钮。
6. 商店地区（账号国）是否也作为合规角标的法域输入之一？当前只作弱信号，法域以用户确认的区域 + 账号国 + 上架地区综合判定，需法务确认优先级。
7. **房间软上限 20 个**是否合适？超过走人工复核；建议保持 20，避免无限房间带来的审核面与 SEO 垃圾房。
8. **留言是否要求「先加入房间才能发言」**？当前原型为登录即可留言；要求加入可显著降低骚扰与刷屏，但会压低首日互动。
9. **`#关键词` 是否允许简繁自动合并**、陌生人 `@` 通知是否维持默认关闭？两者都会影响检索结果与通知量，建议先维持现状（合并词表、陌生人关闭）。

## 14. 区域化组件规范（配套 PRD §26，2026-11-09 增补）

> 全球布局后新增的五个组件。活示例见 `prototype-x-style.html`（首页 v4）；本章是视觉与行为的裁决口径。

### 14.1 设计原则

1. **区域是数据维度，不是站点切换器。** 禁止「切换到英国版」这类换站文案。~~`RegionPicker` 是可叠加的集合~~（v1.9 由 §22 覆盖：当前国家单选，国际频道恒可见且各国共享）。
2. **未启用 ≠ 不存在。** （v1.9：未开通国家不显示国家分类数据，只看国际频道，见 §22。）用户自建内容必须标注用户自建，且**不得使用官方认证徽章**，避免让用户误以为平台已在该法域提供内容服务。
3. **法域按配置渲染。** 合规正文、通知渠道、embed 授权、下架 SLA 全部由 `jurisdiction_policy` 驱动，组件里禁止写死 `UK GDPR · OSA 2023` 之类条款。
4. **位置数据可见、可改、可关。** 默认区域来源（商店地区 / 系统语言 / 自选）必须明示，只到城市级，单独同意；拒绝同意时给「国际频道」兜底包，不得空白页。

### 14.2 组件清单

| 组件 | 职责 | 必需元素 | 禁止 |
|---|---|---|---|
| `RegionPicker` | （v1.9 改为「当前国家」单选，见 §22.2）显示当前国家与国际频道常驻项 | 区域 chips + 移除按钮 + 「添加区域」+ 国际频道常驻项 + 来源说明 | 单选、下拉切换站点、静默定位 |

### 14.3 状态矩阵

|---|---|

**状态不只靠颜色**：文字 + 徽章 + 描边样式（实线 / 虚线）三重指示，沿用 §7 的状态规则。

### 14.4 视觉与 token

| 元素 | 规则 |
|---|---|
| 区域 chip | `--surface2` 底、1px `--line` 描边（≥3:1）、`--r-pill` 圆角；**整块 ≥44px 高，移除按钮触控区 44×44px** |

| 推荐理由 | 前缀「频道数据」用 `--accent-ink`，理由正文用 `--muted`；禁止加粗成主标题 |
| 未启用法域标注 | `--warn` 文字 + 说明文案，仅用于 `RegionPackCard` 底部 |
| 频道推荐卡 | `--surface2` 底 + `--border` 描边 + `--r-lg`；头像沿用频道色，按钮用 `--accent-strong` + `--on-accent` |

### 14.5 无障碍

- `RegionPicker` 用 `role="group"` + `aria-label="我的区域"`；每个移除按钮带 `aria-label="移除{区域}区域包"`。
- `RegionPackCard` 主按钮用 `aria-describedby` 指向「未启用法域」说明；状态变化用 `aria-live="polite"` 播报。
- 所有新增控件满足 44×44px、`:focus-visible` 2px + offset 2px（用 `--focus`）、`prefers-reduced-motion`。
- 移动端 ≤759px：`region-bar` 允许换行，`.region-note` 隐藏但**来源说明必须在设置里可见**；区域包网格降为单列。
- 区域名有 `name_hans` / `name_hant` 两份，禁止前端硬编码中文。

### 14.6 合规 UI（一等组件，不可省略）

| 法域 | `JurisdictionNotice` 必须包含 |
|---|---|
| UK | UK GDPR / PECR 说明、OSA 2023 风险评估入口、NLA 来源署名规则、举报入口 |
| EU | DSA Art 16 通知与 Art 20 申诉入口、内容审核说明、Art 17 相关声明、举报入口 |
| US | DMCA designated agent 联系方式、反通知流程说明、举报入口 |
| 其他 / 未评估 | 「仅展示用户自建频道，平台未在该法域开设官方频道」+ 通用举报入口 |

`RecommendReason` 卡必须带可解释理由与「可关闭」入口；**分类信息、房间单集、外链按语一律不进推荐流**（PRD §22.9）。第三方 embed 的**静态占位卡**自 PRD §27 起可进推荐流，但 iframe 不得在推荐流预加载或自动播放，详见 §15.6。

## 15. 媒体布局与内容优先推荐（PRD §27）

适用范围：首页「为你推荐」/「正在关注」、频道页、房间页的**全部内容卡**。§14 的区域维度、§7 的合规 UI、§2 的 token 与对比度规则全部不废止；本章只改「媒体怎么排」「推荐先给什么」「默认播放怎么成立」。

### 15.1 裁决摘要（与 §20–§26 的差异）

| 项 | 旧口径 | §27 新口径 |
|---|---|---|
| 推荐输出 | 频道卡 + 代表条目两张一组 | **内容卡为主**，频道候选降到列表尾部 |
| 订阅时机 | 先加频道再看内容 | **先消费后订阅**：加入入口固定在卡片右上角 `CardJoinButton`（§17 取代 `FromChannelRow`） |
| 冷启动 | 0 订阅需引导挑频道 | 0 订阅首屏也有 10–20 条内容 |
| 站内播放 | 第三方一律点击才加载 | **第一方默认静音自动播**；第三方首次同意后可默认 |
| 推荐与 embed | embed 卡一律不进推荐 | **静态占位可进推荐**，iframe 不预加载、不自动播 |

§26 的打分公式（`0.40 共现 + 0.30 区域 + 0.20 活跃 + 0.10 精选`）、`region_scope`、可解释理由、`/me/feed?tab=`、统一内容池**全部沿用**，本章只改渲染层与播放偏好层。

> **v1.4 覆盖提示**：本章的「`FromChannelRow` 独立成行」「`MediaCreditBar` 挂在媒体块下方」「`PlaybackPrefBar` 常驻推荐流顶部」三条**已被 §17 裁决废止**；打分、内容优先、两层默认播放、8 种媒体布局、合规红线全部不变，只改这些控件的位置与形态。

### 15.2 媒体布局矩阵

`content.media_layout` 是内容条目上的一个字段，**不是新的 `content_type`**；所有布局共用同一张卡片、同一套来源署名、审核与举报管道。占位色用 `--media-ph-a/b/c`，禁止硬编码。

| 布局 | 适用 | 桌面 | ≤760px | 默认播放 |
|---|---|---|---|---|
| `none` | 新闻摘要、政策要点、纯文字讨论 | 无媒体块 | 同 | — |
| `single` | 单张原创图 / 信息图 | 等比，最大高 510px | 最大高 320px | 静态 |
| `grid2` | 对比图、前后图 | 2 列等分，间隙 2px | 同 | 静态 |
| `grid3` | 房源、探店多图 | 左大右两小（`1.35fr / 1fr`，首格 `grid-row:span 2`） | 同 | 静态 |
| `grid4` | 活动相册 | 2×2，间隙 2px | 同 | 静态 |
| `portrait` | **手机竖屏视频 9:16** | 居中限宽 258px、最大高 460px，两侧 `--bg` 留白 | 限宽 230px / 高 390px | 静音自动播 |
| `landscape` | **横屏视频 16:9** | 全宽 16:9 | 全宽 16:9 | 静音自动播 |
| `embed_ph` | 第三方官方视频 | 静态占位卡 + 来源徽章 | 同 | **禁止自动播** |

圆角统一由外层容器裁切（`--r-lg`）。**v1.4 / §17 裁决**：媒体块下方不得再挂 `MediaCreditBar`，也不得放暂停 / 静音按钮；来源、许可与原创声明统一由卡片级 `SourceLine` 一行承载（显著但只占一行），媒体内部只保留角标（布局标签、视频时长、静音指示图标）与文字替代。

### 15.3 默认站内播放：两层，不能一刀切

| 层 | 内容 | 规则 | 法律/性能依据 |
|---|---|---|---|
| L1 第一方 | 平台自有图片、用户原创视频（`media_origin='original_user'`） | **默认静音站内播放**，可视区自动播；可暂停 / 静音 / 关自动播 | 不引入第三方 cookie，PECR Reg 6 不因播放本身触发；仍需遵守媒体审核与版权确认 |
| L2 第三方 | 白名单官方 iframe | **首次**加载前 PECR 事前同意（仅本次 / 总是允许此平台 / 去原站看）；选「总是允许」后**默认站内播放**；同意可撤回 | ICO：第三方 embed 会传 IP 并设 cookie，一般不符窄豁免；「用户主动请求」需充分告知 |
| 禁止 | 任意 URL、服务端代理 / 转存 / 缓存影片流、带声自动播、推荐流预加载 iframe | 一律拒绝 | §24 三条红线不变 |

**v1.4 / §17 裁决**：`PlaybackPrefBar` 不再常驻推荐流顶部，改为顶部 `SettingsPanel` 内的「播放」分组（右上角齿轮一次点击可达，DSA Art 27 与定位开关同层）。自动播仍是默认行为，用户**不需要也不应该**在每张视频下看到播放 / 静音按钮：下滑进入可视区静音自动播，点按画面本身暂停 / 继续或开声，不喜欢就暂停。「正在关注」/ 设置里可全局关闭自动播。`prefers-reduced-motion`、省流量模式、非 Wi-Fi、离开视口 → 一律降级为静态封面并暂停。

### 15.4 组件清单

| 组件 | 职责 | 关键约束 |
|---|---|---|
| `MediaBlock` | 按 `media_layout` 渲染 8 种布局 | 只消费字段，不新增内容类型；alt 文本必填；**下方不挂任何条 / 按钮**（§17） |
| `SourceLine` | 取代 `MediaCreditBar`：来源名 / 许可 / 原文回链 / N 个来源 | 一行 11px 小字，位于媒体下方、图标操作行上方；显著常驻，不可折叠删除 |

| `CardJoinButton` | 取代 `FromChannelRow`：卡片**右上角**的加入 / 已加入 | 视觉 30px、命中区 44px；未订阅「＋ 加入」、已订阅「✓ 已加入」；`aria-label` 写明频道名；点击即订阅 / 退订 |
| `SettingsPanel` | 取代 `PlaybackPrefBar` / `RecommendParams` 的常驻形态 | 顶部齿轮展开的浮层，含播放 / 推荐 / 区域与定位 / 演示四组；不占信息流高度；内容始终渲染，仅 `hidden` 控可见性 |

### 15.5 状态矩阵

- **媒体（v1.4）**：静态占位 → 下滑进入可视区静音自动播 → **点按画面**暂停 → 再点继续 / 开声 → 离开视口暂停 → 省流量或 `prefers-reduced-motion` 降级静态封面。暂停与静音**不是按钮**，是播放器自身行为。
- **第三方**：占位 → 首次同意面板 → 仅本次 / 总是允许 / 去原站 → iframe 播放 → 收起销毁 → 死链 / 禁嵌入 / 地区未授权自动降级。
- **订阅**：未加入（加入按钮）→ 已加入（退订 + 该频道内容在推荐流降权 `score − 0.12`）→ 切换国家只暂停显示其他国家频道，不影响已有订阅（v1.9）。
- **恒常项**：每张卡必有来源署名 + 许可徽章 + 原文回链 + 举报入口 + 命中区 44px + `:focus-visible` 焦点环（§17.8）。

### 15.6 合规 UI 与推荐放大

1. 推荐流主体是内容卡，但**分类信息、房间单集、外链按语、第三方 iframe 一律不进推荐**；embed 只允许静态占位卡进入，点击后才加载。
2. **OSA 2023**：加回「为你推荐」后，非法内容风险评估必须新增「推荐系统对有害 / 诈骗内容的放大」章节，并记录拦截措施（§20.6 的回退项现在正式生效）。
3. **EU DSA**：Art 27 要求所有使用推荐系统的平台在 ToS 用通俗语言写明主要参数及相对重要性，并在推荐界面直接提供选项切换；我们的 `0.40/0.30/0.20/0.10` 与「正在关注」时间序正好满足。另需评估 Art 17 / illegal content 定义下「未授权版权材料被推荐放大」的风险（§26.3）。
4. **UK GDPR / PECR**：第三方同意写入 `user_consent_log`，可撤回；不因默认播放而采集逐条行为画像；推荐输入仍只用频道级聚合数据。
5. 首版白名单仍只开 YouTube 官方（`youtube-nocookie`），逐法域核对地区授权；大陆限定平台不进白名单。

### 15.7 无障碍与性能

- 视频必须提供文字替代（标题 + 时长 + 内容描述）与 `aria-label`；仅靠颜色不表达状态。
- `IntersectionObserver` 控制播放，`document.visibilitychange` 与离开视口暂停；一次仅一个有声媒体。
- 图片用 `loading="lazy"`、`width/height` 占位防 CLS；媒体块不引入外部字体 / 脚本 / 图片（零外部依赖门禁）。
- 移动端帖子正文 15px / 1.5（v2.3）、两列网格、竖视频限宽防横向滚动；`prefers-reduced-motion` 下全部动效与自动播关闭。

## 16. 自动定位与开通权限（配套 PRD §28，2026-11-09 增补）

> 活示例见 `prototype-x-style.html` v6 顶部定位条 / 区域栏 / 设置浮层与「添加频道」页；展示页第 11、12 节。本章裁决「谁有权创建什么」以及「定位结果能触发什么」；**定位相关控件的摆放由 §17 统一裁决**。

### 16.1 设计裁决：两个问题必须分开回答

| 对象 | 谁能创建 | 理由 |
|---|---|---|
| `region` 区域 / 法域 | **仅平台**（后台配置 + 法域风险评估） | 开一个法域 = 一份风险评估 + 通知渠道 + 下架 SLA + 申诉入口 + 当地语言；用户自建区域会让平台被动 targeting 一个未评估法域 |
| `channel_pack` 官方区域包 | **仅平台** | 绑定 `region.enabled`，由数据库触发器保证未启用区域不得启用包 |
| L1 官方自动 / L2 官方精选频道 | **仅平台**，且只在已启用法域 | 平台是直接内容提供者，责任最重（§21） |
| **L3 用户自建频道 / 房间** | **用户**，任意区域（含未启用法域） | 托管服务责任轻，是「全球」第一天就成立却不承担 N 个法域主动内容责任的关键（§26.2） |
| 加入 / 移除区域包 | 用户（订阅关系） | **不是「开通」**，只是订阅；移除区域不退订频道 |

**一句话**：区域是官方的合规开关，频道是用户的表达空间；**定位只决定先给用户看哪个包，不决定哪个法域被启用**。

### 16.2 定位信号：两个用途，禁止混用

| 用途 | 判定链 | 说明 |
|---|---|---|
| 内容区域（我现在在哪 → 默认展示哪个包） | 已保存的明确选择 → **CDN 边缘 IP 国家级** → 系统语言 / 时区 → 用户自选 → `GLOBAL` 兜底 | 用户确认后 `locLocked=true`，**不再自动覆盖**；VPN / 漫游误判靠在设置中手动切换国家纠正（v1.9 单选） |
| 法域参考（我受谁约束 / 账号国 / 上架地区） | 商店地区（Apple ID / Play 账号国）、账号国、上架地区、用户声明 | **不能当「我在哪」**：商店地区跟账号国走，不跟设备语言、GPS 或 IP，移民用户常滞后于实际所在地 |

- **不用设备 GPS**。ICO 把「不识别个人的城市 / 区域级粗粒度定位」列为可免 PECR 同意的统计目的例外；但 IP 仍是 UK GDPR 个人数据，须透明、目的限定、最小化、可反对。设备 GPS 精确定位才需单独同意与权限弹窗，本产品不申请该权限，也不存 IP 原文与经纬度。
- 只存 `region_code`（国家 / 城市级）+ `source` + 同意记录；`region_source_t` 由 §28.5 用 `ALTER TYPE ... ADD VALUE IF NOT EXISTS 'ip_edge'` 扩一枚值（须独立事务提交），不新建枚举类型、不改 §26 已有表结构。
- **绝不空白页**：定位失败、被拒、或定位到明确排除服务范围的国家 → `GLOBAL` 兜底包 + 合规提示。
- 定位到**未启用法域** → 不显示官方频道包、不给官方认证徽章，只显示用户自建频道 + 国际频道，并提供 `RegionLaunchCard` 的「申请开通」。

### 16.6 无障碍

- 定位条容器 `role="region"` + `aria-label="默认区域确认"`，外层 `aria-live="polite"`；确认后内容变化要能被读屏播报。
- 每个按钮**命中区** ≥44×44px（§17.8：视觉 30–34px 时用 `::after{inset:-7px}` 扩展），移除区域按钮带 `aria-label="移除{区域}区域包"`（沿用 §14.5）。
- 「申请开通」按钮用 `aria-describedby` 指向「仅登记需求，不代表已上线」说明。
- `prefers-reduced-motion` 下定位条无入场动效；移动端 ≤759px 定位条允许换行、`.lc-sp` 隐藏、按钮弹性铺满，**来源说明不得隐藏**。v1.4 起来源告知有**两处**：首次定位条的一行小字 + `SettingsPanel`「区域与定位」分组（常驻可达），因此确认后的细条可以只保留状态摘要，不会丢失 §16.7 的透明性要求。
- 简繁两套区域名与状态文案齐全；深浅两主题都走查过对比度。

### 16.7 合规 UI（一等组件，不可省略）

1. 定位来源与精度**必须可见、可改、可关**；拒绝后给 `GLOBAL` 兜底，不得空白页（UK GDPR Art 6 / 数据最小化 / 反对权；PECR Reg 6 例外的边界见 §16.2）。
2. **自动定位与法域启用必须在界面与代码层彻底分离**：定位结果不得写入 `region.enabled`，不得触发官方频道可见性；业务代码禁止 `if country=='UK'`，一律读 `jurisdiction_policy` 配置。
3. 未启用法域必须显示「仅用户自建频道」，并按用户所在法域渲染 `JurisdictionNotice`（§14.6）；用户自建频道仍走同一套审核、举报与 24h 下架，不因「未开通」而免审。
4. 用户自建频道不得使用官方认证徽章、不得自动进入官方区域包、不得占据「为你推荐」高权重位——避免被认定为「组织、推广大量用户上传作品」而落入 EU DSA / 版权指令 Art 17 的 OCSSP 义务。
5. 「申请开通」只登记需求，用于下一法域排序；文案必须写明「不代表已上线」，且不得作为投票即时开区。

### 17.4 CardJoinButton

- 位置：`card-head` 最右，`flex-shrink:0`，与频道名同排；视觉高度 30px。
- 状态：未订阅「＋ 加入」实心（`--text` 底 / `--bg` 字）；已订阅「✓ 已加入」描边幽灵（`--muted` 字 / `--border` 边）。
- `aria-label` 必须写明「加入频道 {频道名}」/「退订频道 {频道名}」，不能只写「加入」。
- 点击后**即时**同步订阅集合、「正在关注」内容、Tab 计数、右上按钮状态，并写 `recommend_impression.joined_channel=true`；已订阅频道内容在推荐流降权 `−0.12`（§27.4 不变）。
- 频道名已在头部，因此**不再有**「来自频道 X」独立行；区域归属也不在卡片重复。

### 17.5 视频：无按钮，自动播

| 行为 | 实现 |
|---|---|
| 起播 | 第一方视频 `IntersectionObserver` 进入可视区 → `muted=true` + `autoplay`；第三方 iframe 仍禁止自动播 |
| 暂停 / 继续 / 开声 | **点按媒体块本身**（`data-playtoggle` + `role="button"` + `tabindex="0"`，Enter / Space 同样生效），状态写 `data-state="playing|paused"` |
| 静音指示 | 右下角时长角标旁一枚 12px `i-mute` 图标，**纯状态指示，不是控件** |
| 离开视口 / 省流量 / 减少动效 / 非 Wi-Fi | 暂停并降级静态封面 |
| 禁止 | 媒体块下方的 `mbar`、暂停按钮、静音按钮、「不搬运官方图片」说明条、任何 `data-media` 控件 |

理由：X / Telegram 的用户心智是「下滑就播、点一下就停」，额外按钮是冗余认知负担；把播放控制权还给播放器本身，把版面还给内容。

### 17.6 SettingsPanel（顶部浮层）

- 入口：区域栏最右 `⚙`，`aria-expanded` 同步；首次定位条的「详情与开关」是第二个入口。
- 形态：`position:absolute; top:100%; right:0`，宽 `min(420px,100%)`，`max-height:70vh` 可滚，**不占信息流高度**；不遮挡吸顶 Tab。
- 四组：播放（第一方自动播开 / 关、第三方每次询问 / 默认站内播放）、推荐与透明度（DSA Art 27 的 0.40/0.30/0.20/0.10 + 时间序选项 + 冷启动演示）、区域与定位（来源、精度、更改 / 关闭 / 重开 / 重放 / 模拟未开法域）、演示（版本与精简口径）。
- 内容**始终渲染**，只用 `hidden` 控制可见性：保证读屏与自动化门禁都能读到参数，不因面板收起而丢失 DSA 披露。
- 切 Tab 自动收起；再次点击齿轮关闭。

### 17.8 触控与无障碍（重要例外）

X 式紧凑按钮视觉 30–34px 才能保持整洁；**本产品自定的 44×44 目标尺寸不变，但约束对象是命中区而非视觉尺寸**（WCAG 2.2 AA 2.5.8 的 Target Size Minimum 亦按目标区域判定）：

```css
.card-join,.card-more,.reg-gear,.rchip button{position:relative;min-height:30px}
.card-join::after,.card-more::after,.reg-gear::after,.rchip button::after{
  content:"";position:absolute;inset:-7px -3px;  /* 命中区扩到 44px */
}
```

- 命中区不得互相重叠（相邻按钮间距 ≥ 6px，实测 420px 移动视图无遮挡）。
- 图标按钮全部有 `aria-label`；`CardJoinButton` 状态靠**文字 + 图标 + 底色**三重指示，不靠颜色。
- 推荐理由从可见长条收为头部 `why-dot`（`role="img"` + `aria-label` + `title`），悬停 / 读屏仍可读，满足 §26 可解释要求。
- `data-playtoggle` 媒体块可键盘聚焦，Enter / Space 切换播放；`prefers-reduced-motion` 下不自动播。

### 17.9 合规不变项（不得借「简洁」删掉）

1. 每张卡：来源名 + 许可 + 原文回链 + 举报入口（`SourceLine` + `ActionBar`）。
2. DSA Art 27 参数与非画像时间序选项：从推荐界面**一次点击可达**（齿轮）+ Tab 直接可切。
3. 第三方 iframe：推荐流只静态占位、首次 PECR 同意、收起销毁 DOM、不代理不缓存。
4. 自动定位：来源与精度在首次条 + 设置面板两处可见、可改、可关；绝不写 `region.enabled`。
5. 推荐流仍是有限列表，尾部保留「今天先看这些 / 每日 07:00 更新」。

## 18. 多房间小圈子与检索语法（配套 PRD §30，2026-11-09 第十一轮反馈）

> 活示例 `prototype-collection-room.html` v4、`prototype-x-style.html` v7、`publish-content.html`；展示页第 13 节。本章裁决「官方频道 vs 用户房间」的命名与权限、一人多房间、留言评论、`@/#` 语法、AI 关键词与顶部搜索。**不新增颜色 token**。

### 18.1 名称与归属（本轮最容易做错的一层）

| 对象 | 标识 | 徽章 / 后缀 |
|---|---|---|
| 官方频道（`kind=official_auto/curated`） | 认证徽章 +「平台开设」 | 无 |
| 用户房间（`kind=user_created`） | 「用户自建 · 非官方」徽章 + 房主 `@handle` | 房间名必须带「追更房间 / 片单 / 小圈子」后缀 |

**四条硬边界（UI 层必须落实）**：① 用户房间不得用认证徽章、不得命名为「XX 官方」；② 房间封面不得用官方海报（`cover_licence_ref` 非空才展示）；③ 高风险房间 / 单集 / 评论不做置顶、推荐加权、变现；④ 房间页首屏显示「用户自建 · 非官方，与片方无关联」。

### 18.2 组件清单（新增，复用既有 token）

| 组件 | 用途 | 关键规范 |
|---|---|---|
| `TopSearchBar` | 顶部搜索（吸顶层最后一行） | 搜索 SVG + `input[aria-label]` + 44px 搜索按钮 + 清除按钮；`#`→关键词、`@`→用户 |
| `RoomSwitcher` | 我的房间切换（多房间） | 列表含 `room_type`、条目数、父频道；「新建房间」入口 |
| `RoomCommentList` | 房间留言 / 讨论 | 评论、回复、点赞、举报；时间倒序；**不进推荐流** |
| `MentionToken` / `KeywordToken` | `@用户名` / `#关键词` 内联渲染 | **先转义再替换**，可点击跳转用户页 / 关键词页 |
| `AiKeywordChip` | AI 生成的关键词 | 「AI」角标 + `aria-live`；可改可删 |
| `RoomOwnerBadge` | 房主身份 | 侧栏「房主 / 协作者」区 |

### 18.3 留言评论 UI

- 房间页二级 Tab 增加「留言 · 讨论」（`view=comments`），与「内容」「本房间分类信息」并列。
- 评论项：作者 handle + 时间 + 正文 + 回复 / 点赞 / 举报；`@/#` 内联渲染。
- 房主可隐藏评论（软删留痕），不删他人证据链；评论审核 / 24h 下架与内容同管道。
- 空态：「还没有留言，来聊聊这部剧的观后感吧」。

### 18.4 `@/#` 语法渲染（安全硬规则）

```
转义(escapeHtml) → 正则替换 token → 输出，禁止把原文拼进 innerHTML
```
- `#` 后第一个空格 / 标点终止；`@` 只在词首或空白后生效（避免邮箱误判）。
- 关键词 ≤5、提及 ≤10；超出保留纯文本。
- 提及解析不到用户则不生成通知，只渲染文本。

### 18.5 AI 自动关键词

- 触发：用户 `keywords=[]` 时才调用；已填 ≥1 个则 AI 完全不介入。
- 最多 5 个、每个 ≤12 字；每个 chip 带「AI」角标 + `aria-live`；可改可删，改写变 `source='user'`。
- 失败 / 低置信降级为 0–3 个或空，**不阻塞发布**。

### 18.6 验收

`check-rooms.js`：① 顶部搜索在第一条帖子前、可提交 / 清除；② `@/#` 转义后渲染为链接，卡片内无裸 `<script>`；③ 我的房间 ≥2、含 20 集剧房间与电影名房间、标「用户自建 · 非官方」；④ 留言 Tab 可发评论、渲染 @/#、举报常驻；⑤ AI 关键词 ≤5 且用户已填时不触发。

### 22.16 核心业务逻辑与交互闭环组件规范（v2.7，配套 PRD §36.17）

- **RoomFollowingCard（已加入房间在关注流的呈现）**：
  - **位置与排版**：混排在首页「正在关注」Tab 内，按帖子发布时间严格倒序。
  - **卡片头部来源条（RoomOriginTag）**：在卡片作者行上方或作者名右侧，渲染 12px `--accent-ink` 标签：`<button class="room-origin-btn" data-room-open="房间名">来自已加入的房间 · [房间名] ›</button>`，热区 ≥44px，点击平滑直达该房间详情。
  - **右上角操作**：房间帖子右上角仅显示「收藏」与「···」，不显示「关注/加入」按钮（用户已在房间中）。
  - **静音屏蔽**：若房间处于静音状态，关注流过滤时予以跳过。

- **ListingLifecycleActions & ClosedBadge（分类信息生命周期组件）**：
  - **ListingClosedBadge（已结案印章）**：当分类信息被作者标记为已租出/已售出或已下架时，卡片右上角与详情页价格下方渲染专用印章样式：
    - 租房类：`<span class="lst-badge neutral">已租出</span>`；
    - 二手类：`<span class="lst-badge neutral">已售出</span>`；
    - 通用类：`<span class="lst-badge warn">已下架</span>`。
    - 卡片整体增加 `.closed` 样式，图片与文字透明度降为 `0.6`，边框维持 1px `--line`。
  - **ListingActionButtons（作者管理动作栏）**：
    - 仅在作者本人（`l.mine === true` 或 `l.publisher.handle === me.handle`）查看时出现。
    - 未结案状态：提供「标记已租出」（租房）/「标记已售出」（二手），点击后弹出二次确认对话框，确认后打上印章并关闭联系方式。
    - 快过期或已过期状态（`days <= 3` 或 `expired`）：提供「刷新有效期（重置 30 天）」，点击调用 `UKCN.renewListing(id)`，更新 `ts`，重置天数为 30 天，toast 提示「已刷新有效期」。所有按钮高度 ≥36px，触控热区 ≥44px。

- **ListingInquiryDM（分类信息直通私信通道）**：
  - **入口按钮**：在分类信息详情页与卡片操作栏，渲染高优先级「私信咨询」次要主按钮（`<button class="btn-inquiry" data-listing-inquiry="id">私信咨询</button>`），高度 ≥44px。
  - **免拦截机制**：通过该按钮调起 `UKCN.dmOpenForListing(publisher, listingRef)`，直接建立 `status: 'active'` 的正式双向会话，跳过「消息请求」分段与陌生人开关拦截。
  - **ListingMiniCardSnapshot（会话内置房源快照）**：在私信会话气泡区首部或作为固定引文组件渲染：
    - 包含：微缩图（40×40px）、标题（13px 粗体省略）、价格（£xxx，`--accent-strong`）、区域（12px `--muted`）。
    - 附带快捷文本输入预填建议：“你好，想了解一下这套房源是否还在？”。

- **PushedPostCascade（推送级联失效状态处理）**：
  - 频道动态在从 `pushes` 映射拉取帖子时，强制校验底层原帖的实时存在性与审核状态（`orig && orig.status === 'published'`）。
  - 若原帖已被作者在房间内删除或后台封禁驳回，推送卡片从频道动态直接移除，绝不展示空白或断链异常。

- **RoamingCountrySwitch（未开通地区跨国漫游提示与切换）**：
  - **RoamingBanner（漫游提示条）**：当用户定位在未开通国家（如 JP/CA）但主动选择浏览英国站时，顶部区域栏下方展示一行 12px 提示条：`<div class="roam-banner"><span>正在浏览英国站（伦敦）· 跨国漫游模式</span><button class="roam-switch-btn" data-set-country="UK">切回本地</button></div>`，背景 `--surface2`，边框 `--border`。
  - **只读浏览**：漫游模式下对英国频道及租房信息完全开放浏览与私信咨询，但在英国频道尝试发帖时提示“跨国漫游下仅供浏览，发帖请切换至本地”。

- **ContactQuotaNotice（联系方式额度确认与频控通知）**：
  - **额度展示行**：在详情页「查看联系方式」按钮下方，以 12px `--muted` 标注：`今日剩余可查：N / 5 次（为防爬虫与电诈保护）`。
  - **二次确认弹层**：点击后调起 `UKCN.confirm`，明确提示：“查看该联系方式将消耗 1 次今日额度（剩余 N 次）。确定查看？”。
  - **额度熔断态**：当当日剩余为 0 时，按钮置灰禁用，文案变为「今日查询次数已达上限（5次）」，并附带引导文字「可通过“私信咨询”在线联系房东」。
