# 用户房间内容不显示观看平台 UI 设计

日期：2026-11-10  
状态：依用户明确范围实施

## 意图

用户自建房间用于发布讨论、追更记录和片单内容。普通用户帖子、剧集条目和电影条目不应被要求标注“合法观看入口”或观看平台。

## 目标与范围

- 普通用户帖子示例只展示用户写的内容、来源/UGC 标记，不附加观看平台合规文案。
- 剧集条目只收集集号、标题和房主原创按语；移除观看平台选择、平台标签、入口徽章与对应的条目内播放器。
- 电影条目保留现有片名、年份、片长显示和原创按语；表单仍填写片名、年份与按语，不新增片长输入；移除观看平台选择和平台标签。
- 房间页的剧集/电影说明不再宣传或警示观看入口；全局房间侧栏移除观看平台目录。
- 视频房间的官方外链、外链播放同意、原创视频版权确认和举报继续保留，因为它们属于另一种内容类型。

## 非目标

- 不删除视频房间的外链/播放器安全流程。
- 不改变用户帖、留言、剧集和电影条目的发布权限、排序、加入、进度或讨论行为。
- 不修改后端产品数据模型或 PRD 中的平台治理规则。

## 方案与取舍

1. 只删普通帖子样例文案：影响最小，但剧集/电影表单仍会要求填平台，不符合用户刚确认的范围。
2. 移除用户房间普通帖子、剧集和电影 UI 中的观看平台要求（选定）：减少用户自发分享的负担，同时让视频外链仍受既有确认流程保护。
3. 移除所有视频与外链合规 UI：范围过大，会取消用户已确认保留的视频上传与外链播放保护。

选定方案 2。剧集/电影条目改为纯内容记录；视频类型仍使用外链与上传专属控件。

## 约束与验收

- 遵循 `design-system/MASTER.md` v1.7 的 token、组件与无障碍规则；更新房间页覆盖文档中 EpisodeRow / FilmCard 的说明。
- 只改现有单文件原型，不增加外部资源或依赖。
- 剧集、电影表单和条目卡片不再出现观看平台字段、链接或相关空缺状态；视频房间专属外链流程仍可见。
- 普通用户帖子示例不再提到英区合法入口或仅登记状态。
