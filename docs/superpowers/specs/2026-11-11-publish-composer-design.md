# 海外圈发布页优化设计

## 目标

将现有独立发布页优化为更接近 X 的专注编辑体验，并让关键操作更顺手：用户先写内容，再选择发布位置；内容类型选择能直接带出所需字段和操作；提交前能看清审核状态与错误。信息帖直接作为分类信息发布，分类字段按用户选择显示；分类信息仍统一进入频道动态。普通动态仍不要求用户先关注频道。

## 当前状态

- 首页发布入口已打开独立编辑页 `publish-content.html`；因此本次是优化现有页面，不再创建新页面。
- 当前编辑页在正文上方显示发布去向，正文下方始终显示图文、视频、话题、信息四种类型按钮，工具栏又提供图片、视频和话题入口，功能入口有重复。
- 发布位置支持个人动态、房间及从频道详情带入的频道投稿。
- 内容支持图片、视频、话题、信息表单和城市话题；视频需确认原创与授权。
- 结构化分类信息会从共享帖子数据生成分类卡片；频道动态也读取用户投稿，因此目前同一条结构化信息可能出现在两个分区。
- 个人动态、房间和频道投稿遵循现有审核状态；游客发布触发登录或注册。
- 页面已有草稿自动保存、恢复和清空能力；优化时需确保类型、去向和媒体状态在恢复后保持一致。
- 发布页共享数据层副本由 `design-system/sync-shared.js` 管理；本次不修改共享层。

## 方案

1. **保留首页内嵌框，只精简选项**：改动最小，但编辑时仍被首页内容分散注意力。
2. **X 式编辑页优化（选定）**：保留现有独立发布页，正文优先，附件和话题通过工具栏添加，正文下方明确选择发布位置，提交按钮固定在顶部。符合用户提出的 X 式体验，也能容纳现有媒体与内容类型。
3. **分步发布向导**：先选内容类型，再填写内容和去向；步骤较多，不适合普通短帖的快速发布。

## 交互约定

- 保留现有独立编辑页；正文是首要区域。图文为默认形式；视频、话题、信息作为按需添加的内容类型或工具，合并重复入口。
- 发布位置清楚显示个人动态、房间或频道，并说明对应的审核状态；将位置选择放在正文之后。切换目标时即时更新提示，来自频道或房间的入口继续预选正确目标。
- 发布目标保持单一：频道是内容目的地；分类信息使用频道动态中的独立筛选，不提供第二个分类目的地。
- 信息帖标题后必须选择房产、市场或招聘分类，再填写对应结构化字段及一个城市/区域位置字段；所选分类必须与目标频道分类一致，且信息帖只能发布到频道。
- 频道详情只用一条动态列表承载频道帖子、房间推送和分类信息。分类信息作为列表筛选项，分类卡片只渲染一次；不再在频道页另渲染一份独立分类信息清单。
- 选择视频、话题或信息类型后，直接显示对应输入项，并聚焦下一步操作；图片、视频、话题等工具不得出现两个含义不清的重复入口。
- 提交前即时校验当前类型的必填项，并将错误提示放在对应字段附近；提交失败保留草稿和媒体，用户修正后可重试。
- 恢复草稿时还原正文、类型、目标和话题，并说明本地媒体文件需在页面刷新后重新选择；提交失败时保留当前页面中的附件，提供清楚的继续编辑与清空操作。
- 保留现有城市话题逻辑：确认定位后可提示城市话题，并在编辑页醒目展示、允许移除；提交前让用户看清是否会随帖子公开。
- 发布按钮在内容有效时可用。提交时保留现有长度、媒体授权和必填字段校验。
- 提交成功后明确告知“审核中”；网络失败保留草稿，便于重试。
- 游客仍需登录或注册后发布；不要求关注频道。

## 范围与约束

- 优先覆盖首页和移动端发布入口；桌面端复用同一编辑流程并适配宽屏。
- 保留现有审核、帖子模型、房间权限和轻注册流程，不引入新的发布后端能力。
- 真实环境中的审核和服务端发布仍由后端提供；本原型继续使用现有演示逻辑。

## 验收要点

- 用户能从各发布入口进入独立编辑界面，并能返回而不丢失草稿。
- 用户能辨认发布位置、可见范围和审核状态。
- 发布目标切换和类型切换会更新对应提示与字段，入口上下文能正确预选房间或频道。
- 信息帖标题后可选择房产、市场或招聘分类；对应字段、城市/区域位置和频道分类校验均生效。
- 频道页的“全部动态”和“分类信息”筛选共用同一数据源；分类信息不会在同一频道页重复渲染。
- 类型校验错误可定位到需处理的内容；提交失败后草稿仍可继续编辑。
- 草稿恢复保留正文、目标、类型和话题，并清楚说明刷新后需要重新选择的本地媒体；提交失败时当前页面保留附件。
- 图文、视频、话题、信息以及房间投稿现有规则继续生效。
- 游客发布触发登录或注册，登录后回到原发布动作。
- 不关注任何频道的已登录用户仍能提交个人动态。
