# 房间主页 UI 优化设计

日期：2026-11-10  
状态：按用户“继续 UI 开发、写完 Markdown 后直接改 HTML”的既有授权实施

## 意图

继续打磨项目中的房间主页，让窄屏用户能轻松切换房间类型、阅读房间信息并加入或管理更新通知。实现沿用现有原型、设计令牌和 `collection-room` 页面规范，不改业务状态与内容。

## 范围

- 移动端房间类型切换保持单行、支持横向滚动，避免压高吸顶区域。
- 移动端把标题、元信息与通知/加入操作分层排列，按钮保持可见且触控高度至少 44px。
- 轻度提升封面层次与标题可读性，沿用当前封面示例和色彩体系，不加载图片或外部资源。
- 桌面布局、房间类型、通知/加入、季节切换和内容操作维持原行为。

## 非目标

- 不调整频道、房间、帖子数据或操作流程。
- 不重做页面导航、创建表单、内容卡或媒体合规组件。
- 不引入新依赖、图片资源或新的设计 token。

## 方案与取舍

1. **统一压缩桌面和移动布局**：改动少，但会降低桌面信息密度和现有对齐。
2. **移动端定向重排（选定）**：只在窄屏下横向滚动类型控件并重排房间摘要和操作；桌面维持原布局，风险与影响范围较小。
3. **重做完整房间头部**：可以更大幅度更新风格，但超出本轮 UI 延续的范围。

选定方案 2，因为现有独立原型和 `design-system/pages/collection-room.md` 已定义桌面结构，本轮主要问题出现在窄屏的首屏空间。

## 约束

- 遵循 `design-system/MASTER.md` v1.7 和 `design-system/pages/collection-room.md`。
- 使用既有 CSS 变量；控件触控目标 ≥44px；保留焦点环与 reduced-motion 规则。
- 仅改 `prototype-collection-room.html` 样式，并更新本项目计划与进度记录。

## 验收

- 375px 下房间类型保持一行并可横向滚动，不带来页面级横向溢出。
- 375px 下房间标题、说明和通知/加入按钮清楚分层，按钮不被挤出视口。
- 桌面房间头部维持原有左右布局与全部现有交互。
- 浅色和深色主题继续使用现有 token；状态不依赖颜色单独传达。
