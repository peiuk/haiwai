# 「发布」与「我的」页面 · 原型 H5 设计稿逐项对照审查

> 审查对象
> - 设计稿（准绳）：`publish-content.html`（发布页）、`prototype-x-style.html` 的 `renderMe()`（我的页）
> - 实现（待对齐）：`web/src/views/PublishView.vue` + `components/publish/*`、`web/src/views/ProfileView.vue` + `components/profile/*`
> - 设计规范：`design-system/MASTER.md` §17（X 式）、§22（我的页 ProfileHeader 等）、`tokens.css`

---

## 结论摘要

两页实现与设计稿存在**结构性偏差**：原型是「纯 X 式极简」的单输入框 + 内嵌发布流；实现改成了「多 Tab 表单 + 独立卡片布局」，且「我的」页从「分区列表」改成了「Tab 分段导航」。差异集中在 **信息架构 / 布局 / 组件形态 / 文案 / 交互** 五个层面，样式 token 层基本对齐。以下逐项列出。

## 四、修改优先级建议

1. **P0 信息架构**：发布页「三 Tab → 单输入框 + 类型下拉」；我的页「Tab 分段 → 分区列表」。这是最根本的偏差。
2. **P1 顶栏**：发布页补「返回 + 标题 + 发布按钮」顶栏；我的页标题对齐。
3. **P1 发布页 feed**：补「我的发布」折叠区 + X 式帖子卡（含状态 pill、来源署名、许可徽章、举报）。
4. **P2 组件形态**：`type-picker` 下拉、`topics`/`video-block`/`ai-kw`、`seg-toggle`、`status-pill`、`me-row`/`me-section`。
5. **P2 缺失功能**：草稿自动保存、我的举报、删除账号、同意记录、创建房间入口。
6. **P3 导航**：左导航/底部导航结构对齐。

> 备注：实现接入真实后端（`/api/v1/*`），原型为纯前端演示（localStorage）。本次审查聚焦「页面视觉与交互与设计稿一致」，数据层（真实 API vs 演示）的差异在「演示工具（me-demo）」一项中单独标注，不视为 UI 不一致，除非裴总要求演示环境也保持一致。
